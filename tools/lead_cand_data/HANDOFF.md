# 인수인계 — 선행지표 탭(lead.html) 작업 (2026-11-24 기준)

이 세션은 **사이트 「선행지표」 탭과 그 데이터**만 다뤘다. 다른 컴퓨터에서 이어서 하려면 이 문서부터 읽는다.

## 0. 시작 전에
```bash
python tools/gpush.py --pull
```
- **주가 캐시는 저장소에 없다.** `tools/lead_bt_px/`는 깃 제외 폴더다. 백테스트를 다시 돌리면 야후 일봉 670곳을 새로 받고, 15분쯤 걸린다.
- **커밋할 때 주의.** `tools/gpush.py`는 막히면 다른 작업의 커밋 안 된 파일까지 「남은 변경 자동 커밋」으로 올릴 수 있다. 다른 변경이 섞여 있으면 내 파일만 `git add <경로>` → `git commit` → `git push origin HEAD:main`으로 직접 올린다.
- **커밋 안 된 다른 변경은 건드리지 않는다.** 매일 도는 갱신 작업이 남기는 `docs/data/jp/px/*.json`, `docs/data/jp/lead/*.json` 변경 등이 여기에 해당한다.

## 1. 사이트·파일 구조
- **화면:** `docs/lead.html` · `docs/lead.js` · `docs/lead.css`
  - 캐시 무효화는 `lead.html`의 `?v=` 숫자로 한다. 지금 js v37, css v22이고, 다른 작업도 올리고 있으니 올라가 있는 숫자에서 +1 한다.
  - CSP 때문에 인라인 `<style>` 주입이 막힌다. 스타일은 element.style이나 lead.css로 넣는다.
- **기업 원장:** `docs/data/jp/lead/<코드>.json`
  - 항목: `lead.items`(kind: monthly·ext·trends·pension·macro), `lead.macro`(공용 통계 id)
  - 필드: rank·volatile·term_ko·pick_note·thesis
- **공용 통계:** `docs/data/jp/lead/macro/*.json`, 별칭 표는 `macro/index.json`(alias)
- **분기 재무 20분기:** `docs/data/jp/lead/fin/<코드>.json` `{c, q:[{p,end,pub,s,o,n}]}`. TDnet 결산단신 기준이고, 빈 분기는 PDF 표지에서 채웠다.
- **한눈에 표:** `overview.json`
- **튄 지표:** `alerts.json`
- **기존 백테스트:** `bt.json`·`bt/`
- **분기 정렬 백테스트:** `bt_q.json`·`bt_q/`
- **도구(tools/):**
  - 원장: `lead_build` · `lead_apply` · `lead_patch` · `lead_monthly` · `lead_trends` · `lead_ko` · `lead_overview` · `lead_update`(매일)
  - 튄 지표 감지: `lead_spike`
  - 기존 백테스트: `lead_bt`
  - 분기 정렬 백테스트: `lead_bt_q`
  - 후보 채점: `lead_cand`

## 2. 사용자 규칙(반드시 지킴)
- **선행지표 = 밖에서 매달·매주 나오는 데이터.** 업계 판매·정부 통계·수출입 금액/물량/단가·원재료 가격·브랜드/핵심 제품 구글트렌드·다른 회사의 월 매출(대만 동종사 등)은 된다.
- **쓰면 안 되는 것:** 그 회사 자신의 분기 실적·가이던스·KPI, 어느 회사든 분기 매출, 주가지수·ETF·금리·코인, 시장 가격만 보는 지표.
- **후생연금 가입자 수**는 SI·컨설팅만 쓴다. **월차가 있는 회사는 월차를 반드시** 넣는다.
- **섹터로 묶어 일괄로 넣지 않는다.** 기업 하나하나 2단계·3단계 리포트를 읽고 고른다. IP·인물 의존 지표는 「변동 가능」으로 표시한다.
- **큰 변경은 올리기 전에 제안부터 보여 준다.** 답·보고는 한국어로 한다.

## 3. 이 세션에서 한 일(요약)
1. **668곳 지표 재검토 반영.** 리포트 기반으로 다시 고르고, 시장 가격 지표를 뺐다. 월차·브랜드 트렌드도 넣었다.
2. **화면 기능.** 기업 화면에는 다음을 넣었다.
   - 지표 고른 이유를 접는 토글
   - 키 데이터 표시
   - 즐겨찾기: 이름별(민욱·제현·민용), 세 군데 저장 + 백업 코드
   - 실적 발표 임박 접기
   - 재무제표 20분기 표: 실제 발표일 표시, YoY 빨강
   - 주가 위 실적 YoY 겹치기: 매출 노랑·영업이익 보라 점선, % 표시
   - 위 지표 칩 ↔ 아래 「겹칠 지표」 연동
   - 칩에 R값을 정도별 초록색으로 표시
   - 일본어 트렌드 검색어 한국어 뜻
3. **「튄 지표」 페이지(`#spike`)와 감지 스크립트 `lead_spike.py`.** 백테스트 3번으로 기준을 고쳤다.
   - 개선 신호: R ≥ +0.6 · ✅/🔄
   - 원가 급등 경고: 가장 확실
   - ⚡ 빠른 신호: 과열 주의로 분리
   - 수요 하락: 참고만
   - 텔레그램 알림은 아직이다. 봇 토큰은 사용자가 직접 만든다.
4. **20분기 재무 668곳 수집.** 베이커런트 등 7곳은 옛 결산단신 PDF로 빈 분기를 보충했다.
5. **분기 정렬 백테스트 `lead_bt_q.py`**(커밋 5a3523978). 그 분기 지표 → 그 분기 매출 가속/감속 → 공표일~실적 발표 주가로 본다.
   - **실적 방향:** 진짜 지표가 무작위의 2.3배로 맞는다(75% 이상).
   - **주가 방향:** 무작위와 같다.
   - 보고서: `tools/lead_cand_data/lead_bt_q_report.md`
6. **지금 진행 중인 작업: 기업마다 「백테스트로 맞는 선행지표」 찾기**(아래 4절).

## 4. 진행 중 — 기업별 맞는 선행지표 찾기
- **목표(사용자 지시):** 기업 하나하나마다, 일치율이 꽤 높고 매달 트래킹할 수 있는 선행지표를 최소 하나씩 찾는다(전체 약 668곳).
- **도구:** `tools/lead_cand.py <코드>`
  - 후보(`<코드>/cands.json`)와 기존 원장 지표를 같이 채점한다.
  - 실적은 `fin40/<코드>.json`(40분기)을 쓴다.
  - 등급(`p_best` = 그 회사에서 N개 시험한 걸 감안한 우연 확률):
    - 확정: 실적 일치율 ≥ 70% · 분기 ≥ 12 · p_best ≤ 0.05 · 뒤쪽 절반 ≥ 60%
    - 유망: 실적 일치율 ≥ 70% · 분기 ≥ 10 · p_best ≤ 0.20
- **지시서:** `tools/lead_cand_data/BRIEF.md`. 에이전트에게 그대로 준다.
  - 실적 40분기 받기 → 리포트 읽고 후보 최대 6개를 **데이터 보기 전에** plan.json에 적기 → 긴 이력(7년↑) 받기 → 채점
  - 공용 캐시는 `_shared/`, 진행 기록은 `_progress/bNN.txt`, `score.json`이 있으면 건너뛴다.
- **파일럿 10곳 결과.** 40분기 + e-Stat 긴 이력이면 확정이 나온다.

- **주의 — 에이전트가 자꾸 꺼진다.** 이 세션에서는 응답이 끝나면 프로그램이 내려가면서 백그라운드 에이전트가 같이 꺼졌다(세 번). 에이전트를 띄운 뒤 응답을 끝내지 말고, `_progress/` 파일 수를 세는 대기 루프로 붙잡아 두거나, 묶음별로 따로 된 세션에서 돌린다. 결과는 기업마다 저장되니 끊겨도 이어서 된다.
